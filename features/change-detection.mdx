Attaching two images to a single query activates Earth Query Lens's bi-temporal analysis mode. Instead of a single Gemini call, the system runs a staged evidence-fusion orchestration that extracts features from each image independently before cross-correlating them for change detection. The result surfaces a structured summary card, an estimated affected-area percentage, and per-region bounding boxes.

## Triggering bi-temporal mode

Change detection is activated automatically whenever exactly **two** images are present in the submission — either newly attached or carried forward via context reuse. The orchestration entry point is `runOrchestration`:

```typescript
export async function runOrchestration(
  query: string,
  files: File[],
  onProgress: (msg: string) => void,
  signal?: AbortSignal
): Promise<AnalysisResponse> {
  if (files.length < 2) {
    onProgress("Analyzing single image...");
    return analyzeWithGemini(query, files, signal);
  }
  // ...bi-temporal path
}
```

If fewer than two files are provided, `runOrchestration` falls through to a standard single-image `analyzeWithGemini` call.

When two files are present, the orchestration proceeds through three labelled stages with simulated inter-step delays to reflect real-world pipeline latency:

### Execution trace override

After `analyzeWithGemini` returns, `runOrchestration` replaces the default execution trace with a bi-temporal-specific one:

```typescript
res.execution_trace = {
  query: query,
  detected_task: "Bi-temporal Evidence Fusion",
  model: "Sentinel-Fusion-Cluster",
  steps: [
    { name: "Pre-event Extraction",  status: "done", detail: "Extracted baseline features."           },
    { name: "Post-event Extraction", status: "done", detail: "Extracted current features."            },
    { name: "Evidence Fusion",       status: "done", detail: "Synthesized cross-temporal discrepancies." }
  ]
};
```

## The ChangeResult interface

The `change` field of `AnalysisResponse` is typed as `ChangeResult`:

```typescript
export interface ChangeResult {
  change_detected?: boolean;
  changed_area_percent?: number;
  description?: string;
  change_map_url?: string;
  regions?: BoundingBox[];
  confidence?: number;
}
```

| Field | Type | Description |
|---|---|---|
| `change_detected` | `boolean` | `true` if Gemini identifies a meaningful difference between T1 and T2 |
| `changed_area_percent` | `number` | Estimated percentage of the image extent that changed |
| `description` | `string` | Free-text narrative of what changed (e.g. flood extent, building loss) |
| `change_map_url` | `string` | Optional URL to an external change-map raster (not currently populated) |
| `regions` | `BoundingBox[]` | Per-region bounding boxes for localised change areas |
| `confidence` | `number` | Model confidence in the change determination (0–100 or 0–1 scale) |

## ExecutionTrace steps panel

Every assistant response includes a collapsible **Execution Trace** toggle below the change card and evidence chips. Clicking it expands a dark monospace panel listing each pipeline step:

```typescript
{r.execution_trace && r.execution_trace.steps && (
  <>
    <button onClick={() => setTraceOpen(o => !o)}
      className="flex items-center gap-1.5 text-xs ...">
      {traceOpen ? <ChevronDown /> : <ChevronRight />}
      <BarChart3 /> Execution Trace
    </button>
    {traceOpen && (
      <div className="rounded-xl bg-slate-900 text-slate-200 p-4 text-xs font-mono space-y-1.5">
        <p><span className="text-slate-500">task:</span> {r.execution_trace.detected_task}</p>
        <div className="mt-2 space-y-1">
          {r.execution_trace.steps.map((s, i) => (
            <div key={i} className="flex items-center gap-2">
              <Check className="size-3 text-emerald-400 shrink-0" />
              <span className="text-slate-300">{s.name}</span>
              {s.detail && <span className="text-slate-500">— {s.detail}</span>}
            </div>
          ))}
        </div>
      </div>
    )}
  </>
)}
```

The `ExecutionStep` type used by each row:

```typescript
export interface ExecutionStep {
  name: string;
  status?: "pending" | "running" | "done" | "failed";
  detail?: string;
}
```

## T1/T2 image overlays with grounding boxes

When two images are submitted, the response bubble renders them side-by-side in a two-column grid. Grounding bounding boxes from `AnalysisResponse.grounding` are drawn over each image using the `BboxCanvas` component:

```typescript
{idx === 0 && img.previewUrl ? (
  r.grounding && r.grounding.length > 0 ? (
    <BboxCanvas
      url={img.previewUrl}
      boxes={r.grounding}
      label="T1: Pre-Event"
      onClick={() => onImageClick(img.previewUrl!, r.grounding!, "T1: Pre-Event")}
    />
  ) : /* plain img with T1 label badge */
) : idx === 1 && img.previewUrl ? (
  r.grounding && r.grounding.length > 0 ? (
    <BboxCanvas
      url={img.previewUrl}
      boxes={r.grounding}
      label="T2: Post-Event"
      onClick={() => onImageClick(img.previewUrl!, r.grounding!, "T2: Post-Event")}
    />
  ) : /* plain img with T2 label badge */
)}
```

See [Bounding Box Overlays](/features/bounding-box-overlays) for full details on how boxes are drawn and colour-coded.
